# TrinityAI Business OS — Frontend (Phase 1)

React + TypeScript + Tailwind, built directly off the 8 locked Stitch
screens and `saas_business_os/DESIGN.md`. This is a **fully working,
standalone app** — it runs entirely client-side against an in-browser store
(`localStorage`-persisted via Zustand), so you can `npm install && npm run
dev` and use every module immediately with no backend required.

See `../backend` for the API/database scaffold this is designed to plug
into later, and the repo-root `PHASE_STATUS.md` for what's implemented vs.
what's next.

## Running it

```bash
npm install
npm run dev       # http://localhost:5173
npm run build     # production build -> dist/
npm test          # runs the Vitest suite (24 tests: calculations + cascades)
```

## What's real vs. what's a placeholder

- **Real, computed from live state:** every KPI, chart, table, and kanban
  board. Nothing is hardcoded — an empty workspace shows the exact
  empty-state pattern from Screen 1/2/5 (icon, message, inline "+ Add"),
  never a fake number.
- **Real cascades:** converting a lead creates a Client + Contact + Deal;
  dragging a deal to "Won" creates a Project + starter Tasks + a draft
  Invoice; recording a payment updates the invoice, adds a revenue ledger
  entry, and can surface an upsell insight — see `src/lib/cascades.ts`.
- **Real Excel export** (`src/lib/export.ts`, via SheetJS) on every list,
  plus one "Export Everything" workbook on the Reports page, and a working
  CSV/XLSX import wizard (upload → column-mapping → confirm) for Leads on
  the Settings page.
- **Demo data** (Settings → Load Demo Data) is clearly `is_demo`-flagged and
  can be reset without touching anything you've entered yourself.
- **Placeholder:** the AI Advisor's insights are generated by simple rules
  over your data (e.g. "this invoice is overdue"), not an LLM — wiring a
  real model behind `AIService/ProviderAdapter` (spec Section 4) is Phase 7.
  Document uploads record file metadata only; actual file storage is a
  Phase 9 integration.

## Project structure

```
src/
  types/          Core data model (mirrors backend/prisma/schema.prisma)
  lib/
    store.ts       Zustand store — the client-side "service layer"
    calculations.ts  Centralized calc functions (revenue, MRR, CPL/CAC/ROAS, health score...)
    cascades.ts     Lead→Client/Deal, Deal Won→Project/Invoice, Payment→Revenue
    seed.ts         Demo data generator (is_demo: true)
    export.ts       Excel export/import (SheetJS)
  components/
    ui/             Design-system primitives (Button, Card, KPICard, DataTable, KanbanBoard...)
    layout/         AppShell, Sidebar, Topbar, mobile nav
    charts/         TrendChart (solid + dashed line pattern from Screen 8)
  pages/            One folder per nav group (crm, operations, finance, marketing, growth, ai)
```

## Design tokens

copied verbatim from `stitch_trinityai_business_os/saas_business_os/DESIGN.md`
and the 8 `code.html` files — nothing here was redesigned or reinterpreted.
